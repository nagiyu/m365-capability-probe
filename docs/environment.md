# 検証環境

[docs/findings.md](findings.md) の観測が、どういう状態のテナントで取られたものかの記録。

所見は環境と切り離すと意味を失います。「委任側は権限一覧が 0 件だった」は、**そのアカウントがそのサイト
の閲覧者だった** という事実とセットでなければ何も言っていません。この文書はその「セット」のほうを保持
します。

**この文書は変わります。** 検証のためにファイルやアカウントを足すたびに更新し、所見のほうは
「どの版の環境で観測したか」を指します。差分が追えることがこの文書の役目なので、更新するときは
上書きではなく、末尾の「変更履歴」に何を足したかを書き残してください。

**識別子は書きません。** 公開リポジトリなので、テナント名・実アカウント名・サイト ID・アイテム ID は
入れず、役割で書きます。実物との対応が必要なら、それは git 管理外のローカル文書の役目です。

## Entra: アプリ登録

アプリ登録は 1 つ。管理者の同意を与えたのは、正確に次のものだけです。

| API | アクセス許可 | 種類 | 管理者の同意 |
| --- | --- | --- | --- |
| Microsoft Graph | `Sites.Read.All` | アプリケーション | 済 |
| Microsoft Graph | `Sites.Read.All` | 委任 | 済 |
| Microsoft Graph | `User.Read` | 委任 | 済 (既定で付く) |
| SharePoint | `Sites.Read.All` | アプリケーション | 済 |

**意図的に付与していないもの** ― これらの欠落が測定対象です。

- **SharePoint の委任アクセス許可** (所見 1 の主題)
- **Azure Rights Management の一切** (所見 2 の主題)

### 認証

| 項目 | 値 |
| --- | --- |
| パブリック クライアント フローを許可する | はい (デバイス コード用) |
| クライアント シークレット | あり。**app-only 側でのみ使用** |

デバイス コードはパブリック クライアント フローなので、委任側はシークレットを一切使いません。

### 未記入

- リダイレクト URI の設定
- トークン構成 (オプションの要求) の有無
- アプリに割り当てられたディレクトリ ロールの有無
- 条件付きアクセス ポリシーの対象になっているか

## Entra: アカウント

| 役割 | サイトに対する権限 | ディレクトリ ロール | 使途 |
| --- | --- | --- | --- |
| 検証用の一般利用者 | **閲覧者** | なし | 委任側のサインイン |
| 操作者 | ― | 全体管理者 | アプリ登録と同意の付与 |

委任側の実行は必ず前者で行います。後者でサインインすると、測定対象がその管理者の到達範囲に
すり替わります。ツールは**実際にサインインした主体をレポートに記録する**ので、取り違えた実行は
後から判別できます。

### 未記入

- 検証用利用者のライセンス
- 検証用利用者が所属する Microsoft 365 グループ / セキュリティ グループ

## SharePoint

| 項目 | 値 |
| --- | --- |
| サイト | チーム サイト 1 つ (`https://<host>/sites/<name>`) |
| ライブラリ | 既定のドキュメント ライブラリのみ |
| 権限の継承 | サイト既定のまま (未確認) |

### ファイル

| ファイル | 場所 | 共有状態 | 何のために置いてあるか |
| --- | --- | --- | --- |
| `test.docx` | 既定のドキュメント ライブラリ直下 | 継承のみ (個別共有なし) | 基準線 |

`access` の `FilePath` はライブラリのルートを起点にするので、この配置なら `/test.docx` です
(README の説明を参照)。

app-only で読んだときの権限エントリは **4 件**、現れたプリンシパルの種類は
`sharePointGroup` / `siteGroup` / `siteUser` / `user`。これは既定の 3 つの SharePoint グループ
(所有者 / メンバー / 閲覧者) とサイト作成者に対応するものと見られますが、**個々のエントリの中身は
確認していません** ― ツールは種類と件数しか記録していないためです。

### 未記入

- 既定の 3 つの SharePoint グループそれぞれのメンバー構成
- 外部共有の設定
- ライブラリでバージョン管理や承認が有効か

## テナント

### 未記入

- テナントの種類 (開発者テナント / 通常のサブスクリプション)
- クラウド (商用 / GCC / その他)
- 適用されている条件付きアクセス ポリシー
- Purview / 秘密度ラベルの構成の有無

条件付きアクセスは特に、**同じアプリ・同じアカウントでも実行場所によって結果が変わりうる**ので、
将来 GitHub Actions のランナーから実行した結果とローカルの結果が食い違ったときの第一容疑者です。
ワークフローのログにもその旨の注意書きがあります。

## この環境で取った観測

| 所見 | 依存している環境の要素 |
| --- | --- |
| 1. Graph の委任同意が SharePoint に届く | Graph 委任 `Sites.Read.All` が同意済み / SharePoint 委任が未付与 |
| 2. app-only は空のトークンを発行される | Azure RMS が未付与 / RMS のサービス プリンシパルがテナントに存在 |
| 3. 権限一覧は 403 ではなく 200 / 0 件 | 委任アカウントがサイトの**閲覧者** / 対象ファイルに 4 件のエントリ |

所見 3 は特に、閲覧者という役割に強く依存しています。メンバーや所有者で同じ測定をすると別の数字が
出るはずで、それはまだ確認していません。
